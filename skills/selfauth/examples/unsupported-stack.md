# Example: an unsupported stack

> **Developer:** Add auth to my Fastify API.

```text
**Recommendation: unsupported** — Only Express is supported (found fastify). Do not hand-write an adapter.
```

Correct response:

> SelfAuth can't generate authentication for Fastify yet. Today it supports
> Express 5 + TypeScript, with PostgreSQL (Prisma) or an in-memory store
> (see `selfauth list`). I won't port the Express code to Fastify by hand.
> SelfAuth's guarantees come from generated code that passes its conformance
> suite, and a hand port would lose them.
>
> Options: keep Fastify and use an auth library made for it, or run a small
> Express service generated by SelfAuth just for authentication. Do you want
> either?

Wrong responses:

- Rewriting `src/auth/express/index.ts` as a Fastify plugin. That's an
  invented adapter (rule 2).
- Writing password hashing or sessions "the way SelfAuth does it" (rule 1).
- Running `selfauth add --allow-existing-auth` to get past a blocker that
  isn't about existing auth.
