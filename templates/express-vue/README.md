# selfauth-app

Generated by SelfAuth. **All of this code is yours**: read it, change it,
deploy it. Nothing here calls a SelfAuth service.

## Run

```bash
npm install
cp server/.env.example server/.env   # then set DATABASE_URL
npx selfauth db plan          # optional: review the migration for destructive changes
npm run db:migrate
npm run db:seed               # roles from server/src/config/selfauth.config.ts
npm run dev                   # API on :3000 and the vue app together
```

Open http://localhost:5173. The API is in `server/` and the vue frontend in `client/`; they are two packages in one npm workspace, so one `npm install` at the root installs both and `npm run dev` starts both (the frontend proxies /auth and /api to the API). The frontend's `src/auth/` holds the API client, session state, route guards and `<Can>`. The `notes` example (backend `server/src/routes/notes.ts`, frontend notes page) shows permissions and ownership: replace it with your own features.

The backend only trusts the frontend origin in `SELFAUTH_APP_BASE_URL` (`server/.env`). If you serve the frontend elsewhere (for example `vite preview` on another port, or a deployed domain), set that variable or add the origin to `http.trustedOrigins`, or state-changing requests fail with CSRF_FAILED. See https://github.com/thetejasmagade/selfauth/blob/main/docs/frontend-deployment.md.

Email (verification, password reset) is printed to the console in
development. Before production, implement `createMailer()` in
`server/src/email/mailer.ts`; the server refuses to start in production until you do.

```text
    http/                        error responses and request ids

  test/                          smoke tests for the authentication wiring (npm test)
  prisma/                        database schema and migrations
  package.json, tsconfig.json    its own package

  src/
    main.ts, App.vue, router.ts  entry point, app shell and routes
    auth/                        SelfAuth's frontend module: API client, session state, route guards, <Can>

  package.json                   its own package

```

Authentication behaviour is configuration (`server/src/config/selfauth.config.ts`), not code you
edit: `server/src/auth/` is the tested security core.

## Routes

Authentication lives under `/auth` (register, login, logout, me, email
verification, password reset/change, sessions, admin). Add your own routes in
`server/src/routes/index.ts`; guard them with `auth.requireAuth`,
`auth.requirePermission("x.y")` or `auth.protectedRoutes()`.

Browsers must send `X-SelfAuth-CSRF: 1` on state-changing requests (or use
the SelfAuth frontend client).

Create the first administrator after registering: `npm run db:create-admin you@example.com`.

## Checks

`npm test` runs smoke tests of the authentication wiring in `server/test/` (no database needed).
They are yours to extend. The SelfAuth CLI is a development tool and optional; the app never
needs it to run.

```bash
npx selfauth doctor     # configuration and production-readiness warnings (checks server/ and client/)
npx selfauth validate   # configuration schema + which generated files you changed
npx selfauth diff       # what a newer SelfAuth release would change
```
